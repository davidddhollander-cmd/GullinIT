# Pixel art consistency audit — 27 October 2026

Run by Claude on the `GullinIt-main` worktree, against every PNG the game loads at runtime (100 files, 96 on-screen uses). Tools, palette and manifest are in `tools/art_audit/`; the full machine report is `assets/archive/previews/art-audit-2026-10-27/report.md`.

**Result: 44 S1, 18 S2, 7 S3, 8 S4.** The palette, outline colour and warm 32-bit look already hang together. The real break is **pixel size**: 29 sprites are drawn at a scale that is not a clean multiple of the cast standard, so their pixels come out uneven and shimmer in motion. The gulls, the player's own character, are the most visible case.

## How changes get approved

Agents cannot reliably judge how art looks on screen, so this audit's numbers say **where to look**, not what is wrong to the eye. Every art change goes through the Art Lab (task 044) first: a test level that shows the current art and a candidate side by side, moving as in play, at real size and 4×, with a blind A/B mode. Candidates are registered only in `data/art_lab.json`. **David approves each one by eye before it touches the live game**, and anything he can't see a difference in is dropped. The gull work starts with the herring only (task 046) and stops there if the difference isn't visible.

## Standard used

Task 033 and the approved diner-led pilot (19 Oct) set the cast standard: **128 px cells drawn at `visual_scale` 0.5**, about 40 px tall. Shoppers, vendors, lifeguard, sunbathers, mum, toddler, dog owner, market cleaner and diner B all follow it. Each sprite is measured against that standard:

- **texels per art pixel = 0.5 ÷ visual_scale.** 1 = on standard. A whole number (2, 4) = finer art thrown away evenly (S2). Anything else = uneven sampling and shimmer (S1).
- Props stay hand-pixelled at 1:1 on the 320×180 grid (see `RETRO_ENVIRONMENT_STYLE.md`), so their pixels are 2× chunkier than the cast's. That is reported once, as a decision, not a defect.
- `canvas_items` stretch mode is **correct** for this standard. Switching to `viewport` would render at 320×180 and the 0.5 sheets would lose half their pixels (checked: gull eyes and beaks vanish, crabs turn to noise).

Lineups at 1280×720 (current renderer): `assets/archive/previews/art-audit-2026-10-27/lineup_canvas_items.png`; same art forced to 320×180: `lineup_viewport.png`.

## Decisions for David

1. **Props vs cast pixel size.** Props draw 1:1 (each texel is 2×2 cast pixels). Either accept "chunky world, finer cast" as the look, or redraw the 23 props and 6 VFX at double resolution and 0.5 scale. Recommendation: accept for the demo; it reads as foreground vs scenery and costs nothing.
2. **Painted cast vs flat props.** The cast averages about 430 colours on screen and 70% off the prop palette; props average under 25 and are on-palette. Options: leave it (approved diner-led style), or run a palette-snap pass on the cast. Recommendation: leave it, but hold new props and VFX to the palette.
3. **Lock the palette.** `tools/art_audit/palette.hex` holds the 19 colours the props share, outline `#183b4e` first. It is derived, not designed. Confirm or replace it.

## Re-running

```
pip install pillow numpy
python tools/art_audit/build_manifest.py > tools/art_audit/art_manifest.json
python tools/art_audit/gullinit_audit.py --project . --manifest tools/art_audit/art_manifest.json --palette tools/art_audit/palette.hex --out test-output/art_audit
```

Rebuild the manifest whenever sprites are added or a `visual_scale` changes. Scales set in code (adult 0.5, stand-sign width 64, beach-sign 8 px rows, logo 175×26, loading backdrop) are hard-coded in `build_manifest.py`; update them there if the code changes. Exit code 1 means S1 findings remain.

What the script cannot judge: light direction, animation timing and readability at speed. Those stay manual (Tier 2 and 3 of the audit process).
